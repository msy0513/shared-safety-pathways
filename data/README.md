# Data

> **Content warning.** `train_data/` and `eval/` contain harmful requests (violence,
> weapons, hate speech, etc.). They are released only for safety research.

All files are plain JSON / JSONL.

```
data/
├── train_data/<lang>/final_safe.jsonl   D^-_λ and D_train: harmful query + safe refusal
├── benign/en.json                       D^+: 1,000 English benign (Alpaca) queries
├── benign/alpaca_1000.json              their source (instruction/input/output)
├── eval/advbench_x_json/<lang>.json     {"safety": AdvBench-x prompts}
├── eval/multijail_json/<lang>.json      {"safety": MultiJail prompts}
└── scripts/                             construction / translation scripts
```

The translated benign queries `benign/<lang>.json` are not shipped; they are generated with
one command (Sec. 2 below).

`train_data/` and `benign/` cover EN and the nine NHR languages (`train_data/` uses the
directory name `zh-CN` for Chinese). `eval/` additionally contains JP and AR.

## 1. Safety data: `train_data/`

Each line is `{"instruction": <harmful query>, "response": <safe refusal>}`.

* **Source.** The English queries come from Aegis 2.0 (Ghosh et al., 2025) and
  JailbreakBench (Chao et al., 2024), each paired with a safe refusal.
* **Other languages.** Line-aligned machine translations of the English file, for example:

  ```bash
  python data/scripts/translate.py train --src data/train_data/en/final_safe.jsonl \
         --out data/train_data/sw/final_safe.jsonl --lang sw
  ```

These files serve two purposes:
* **D^-** (unsafe context of the probing data, Sec. 3.1) of each language;
* **D_train** (cross-lingual safety corpus, Sec. 4): all pairs of the training languages.

## 2. Benign data: `benign/` (D^+)

`benign/alpaca_1000.json` holds 1,000 Stanford Alpaca examples (Taori et al., 2023) and
`benign/en.json` their `instruction` field, the benign context D^+ of English. The other
languages use machine translations of these queries:

```bash
bash data/scripts/translate_benign.sh                                     # Google Translate
BACKEND=llm LLM_API_KEY=... LLM_MODEL=... bash data/scripts/translate_benign.sh   # LLM API
```

If a translation request fails, the English sentence is kept in place and a warning is
printed; re-running the command retries exactly those items. The responses of D^+ are
generated by the model during pathway identification (`pathway/extract_ffn_activations.py`).

## 3. Evaluation data: `eval/`

| benchmark | prompts / language |
|---|---|
| AdvBench-x (Yong et al., 2023) | 520 |
| MultiJail (Deng et al., 2024) | 315 |

Languages without an original version are machine-translated from English.

```bash
python data/scripts/build_eval_sets.py --advbench-x-csv advbench_x.csv \
       --multijail-csv MultiJail.csv --out-dir data/eval \
       --langs en zh ko bn th sw hu af it ne jp ar
```

## Translation backends

`data/scripts/translate.py` supports two backends:
* `--backend google` (Google Translate);
* `--backend llm`, an OpenAI-compatible endpoint configured by `LLM_API_KEY`,
  `LLM_BASE_URL` and `LLM_MODEL`.
